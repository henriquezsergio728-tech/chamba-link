# 0008. API conventions

## Context

The API served `GET /healthz` with Fastify defaults: plain JSON error bodies, request ids that the client could not supply, no security headers, configuration read ad hoc from `process.env`, and no signal handling. Inside the image, `node` runs as PID 1 (`CMD ["node", "dist/server.js"]`). Linux does not apply a signal's default action to PID 1, so without a handler the process ignores the `SIGTERM` from `docker stop` until Docker kills it after the grace period. Routes with request bodies, a database connection and clients that correlate requests need these settled once, before they are built on.

## Decision

**Errors.** Every error response is RFC 9457 problem details with content type `application/problem+json`, built in [`api/src/errors.ts`](../../api/src/errors.ts):

```json
{ "type": "about:blank", "title": "Not Found", "status": 404, "detail": "Route GET /x not found", "instance": "/x", "requestId": "..." }
```

- An `AppError` with a status below 500 returns its own `status`, `title`, `detail` and `code`, plus any `extensions` as extra members.
- A request that fails schema validation returns `400` with an `errors` array of `{ path, message }`, where `path` starts with the request part, for example `body/name`.
- A 4xx error raised by Fastify itself, such as a malformed JSON body, keeps its status and message.
- Any other error, including an `AppError` with a status of 500 or above, returns `500` with the detail `Internal Server Error`. The error is logged with the request id and never returned. A database error raised through Drizzle is logged without its query parameters: `describeError` keeps the error name and the database error's `code`, `constraint`, `table`, `schema` and `message`, and drops the query, the parameters and the pg `detail` field.
- An unknown route returns `404` from the not-found handler.

**Request ids.** An incoming `x-request-id` is used as the request id only if it matches `^[A-Za-z0-9._-]{8,64}$`, so a client cannot write arbitrary text into the logs. Otherwise the API generates `crypto.randomUUID()`. Every response, including error responses, carries the id in `x-request-id`, and problem bodies repeat it as `requestId`.

**Configuration.** `buildApp()` takes no arguments, reads no configuration and opens no database connection, so tests build the app with `buildApp()` and call it through `inject`. The entry points `api/src/server.ts` and `api/src/migrate.ts` validate the environment with TypeBox schemas in [`api/src/config.ts`](../../api/src/config.ts) before doing anything else. On failure they print each invalid variable's name and whether it is `missing` or `invalid`, never its value, to stderr, and exit with code 1. `server.ts` then registers the database plugin ([`api/src/db.ts`](../../api/src/db.ts)) on the built app.

**Health check.** `GET /healthz` is a liveness check. It returns `{"status":"ok"}` without querying Postgres, and stays at the root path, outside the versioned prefix.

**Security headers.** `@fastify/helmet` sets its default headers, with two turned off:

- `Strict-Transport-Security`, because clients connect to Cloudflare, not to the origin, and whether to send HSTS is an open decision at the Cloudflare layer.
- `Content-Security-Policy`, because the API returns JSON and serves no documents for a policy to protect.

**OpenAPI and versioning.** `@fastify/swagger` generates an OpenAPI 3.1 document from route schemas, served at `GET /v1/openapi.json`. No documentation UI is served. Application routes live under the `/v1` prefix; `/healthz` is the exception. Route schemas are TypeBox schemas, and `@fastify/type-provider-typebox` infers handler types from them. Routes are registered inside plugins so that they load after `@fastify/swagger` and appear in the document.

**Shutdown.** On `SIGTERM` or `SIGINT`, `server.ts` calls `app.close()`, which stops accepting connections, lets in-flight requests finish and ends the Postgres pool, then exits with code 0. If closing takes longer than 8 s it exits with code 1, inside `docker stop`'s 10 s grace period. A second signal during shutdown is ignored.

## Consequences

- Clients can parse every error body the same way and quote `requestId` when reporting a problem.
- A route that needs a specific client-facing error throws `AppError`; any other thrown error becomes a generic 500.
- A request id generated by a client or an upstream proxy carries through to the logs only if it passes the pattern.
- The API refuses to start without a valid `DATABASE_URL`. The CI smoke test passes a placeholder URL, which works because the pool connects lazily and `GET /healthz` does not query Postgres.
- `/healthz` reports the process as live even when Postgres is unreachable.
- Origin responses carry no `Strict-Transport-Security` header.
- The OpenAPI document lists only routes registered inside plugins after `@fastify/swagger`.
- `docker stop` on the API container returns once the app has closed.
